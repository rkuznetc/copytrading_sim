# Итерация 1. Воспроизводимые наборы данных

## Исходная версия

Основа — архив `git archive` от коммита
`f6c3c89b8af0664ebe0f06d281ba87af8bcca27d`. Идентификатор прочитан из комментария ZIP.
В исходном снимке было четыре теста: импорт пакета и загрузка небольшого конфига.
Экспорт, структурная проверка и несколько будущих модулей были пустыми.

## Границы итерации

Задача: сохранить проверенный запуск так, чтобы его можно было воспроизвести,
загрузить и далее использовать с централизованными и федеративными моделями.
Не менялись коэффициенты совместимости, распределения архетипов, формулы показа
и отклика. Не добавлены интерфейсы новых рекомендателей, обучение, финансовые
временные ряды или замкнутый цикл.

## Изменения по коммитам

1. `feat: resolve run configuration and isolate random streams`
   — полная конфигурация с дефолтами, явные YAML-переопределения, строгая проверка
   настроек, отдельные потоки случайности и конфигурационный отпечаток.
2. `test: enforce table invariants and preserve empty event schema`
   — обязательные структурные проверки, полная схема пустой `copy_events`,
   тесты некорректных данных и пограничных случаев.
3. `feat: persist validated runs with provenance and verified CSV loading`
   — CSV-экспорт/загрузка, контрольные суммы, версия кода и окружения, новый CLI.
4. `docs: document reproducible runs and clean generated package metadata`
   — инструкция, допущения, актуальная спецификация и исключение артефактов сборки.

## Случайность и воспроизводимость

Схема `seedsequence-pcg64-v1` использует `SeedSequence(root_seed, spawn_key=(stage_id,))`
и явный генератор `PCG64`. Стабильные номера потоков: пользователи — 0, стратегии — 1,
показы — 2, отклики — 3. Номера существующих потоков нельзя менять при добавлении новых.
`random.seed` — целое число от 0 до `2**63 - 1`.

Это даёт изоляцию **между этапами**: число пользователей не меняет каталог стратегий,
а настройки отклика не меняют уже сгенерированные показы. Внутри этапа порядок
вызовов по-прежнему важен. Здесь ещё нет независимых потоков для каждой пары
пользователь--момент или гарантии одинакового шума при сравнении разных политик.

Данные с seed 42 после изменения схемы не обязаны совпадать с данными старого
прототипа. Для старых результатов нужна старая версия кода. Новый код и то же
окружение воспроизводят таблицы точно; межверсионная/межплатформенная побитовая
воспроизводимость не гарантируется.

## Конфигурация и происхождение

`config.resolved.yaml` содержит все используемые конфигурируемые параметры:
размеры, seed, совместимость, показ, отклик и выходной каталог. Нечисловые/неконечные
значения, опечатки ключей и неподдерживаемые форматы не принимаются.

**Не все константы генераторов перенесены в YAML.** Средние архетипов, вероятности
категорий и некоторые коэффициенты остаются в коде. Поэтому manifest содержит
хеши всех `.py` файлов пакета, `pyproject.toml`, общий отпечаток исходников,
Git-коммит и флаг незакоммиченных изменений, когда Git доступен. Если `.git` нет,
коммит имеет значение `null`, но отпечаток реальных исходников сохраняется.

При изменённом рабочем дереве Git-коммит сам по себе не описывает точный код:
для воспроизведения нужно сохранить изменения или зафиксировать их коммитом.
Отпечаток позволяет сверить код, но не восстанавливает его из хеша.
`requirements.runtime.txt` фиксирует основные библиотеки, а не заменяет полный
платформенный lock-файл окружения.

Конфигурационный хеш не включает выходной каталог. `dataset_sha256` вычисляется
по семи CSV-таблицам. Повторный экспорт тех же данных под другим именем имеет тот же
идентификатор набора; время создания и имя запуска при этом отличаются.
Контрольные суммы предназначены для обнаружения изменений, а не для защиты от
намеренной подмены данных вместе с manifest.

## Договорённости о таблицах

`exposures_per_user` — число списков показа на пользователя, а не число строк.
При U пользователях, I стратегиях, T списках на пользователя и K позициях:

- users: U строк; strategies: I строк;
- compatibility: U * I строк;
- exposures и copy_decisions: U * T * K строк;
- copy_events: от 0 до U * T строк;
- metadata: одна строка.

Пустая `copy_events` теперь имеет те же колонки и типы, что непустая: это исправление
контракта данных, а не изменение модели отклика. В `metadata` добавлены число
списков, доля списков с копированием, схема случайности и отпечаток конфигурации.

## Приёмка итерации

1. Выполнить `python -m pytest -q`.
2. Запустить CLI с `configs/small.yaml`.
3. Загрузить сохранённый каталог через `load_run`.
4. Повторить генерацию по сохранённой конфигурации; сравнить таблицы.
5. Проверить отказ при повторном `--run-id` и при испорченном CSV.

Следующая итерация — отделение источника оценок рекомендателя от формирования
списка показов и от модели отклика. Для неё уже есть фиксируемые наборы данных.
