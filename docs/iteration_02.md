# Итерация 2: подключаемые рекомендации и первые эксперименты

## Результат и границы

Симулятор теперь можно использовать с внешним рекомендателем: единый интерфейс
получения оценок, правило отбора списка и модель отклика разделены. Добавлены
простые политики, централизованная логистическая матричная факторизация и
воспроизводимый эксперимент с графиками. Федеративных раундов и автоматического
обучения по новым откликам здесь ещё нет. Эта итерация объединяет архитектурный
шаг и первые централизованные сравнения, не утверждая завершение всего симулятора.

Начальная база — архив первой итерации, Git-дерево
`d4af2b17a9122e62466bbe5c980f5ed3c55fb9e9`. Новые коммиты применяются **на текущей
ветке существующего запроса на слияние**; новую ветку или новый запрос создавать
не нужно. Хеши коммитов после `git am` могут отличаться от авторских.

## Быстрый запуск

Из корня проекта, внутри существующего виртуального окружения:

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python -m copytrading_sim.experiments \
  --config configs/experiments/quick.yaml --run-id iter2-quick
```

Откройте `artifacts/experiments/iter2-quick/report.html` в браузере или `report.md`
в редакторе. PNG и SVG находятся в `figures/`. Существующее имя запуска нельзя
перезаписать: используйте другое `--run-id` или опустите этот аргумент.

Обычная генерация из первой итерации сохранена:

```bash
python -m copytrading_sim.main --config configs/small.yaml --run-id dataset-new
```

Серия из трёх независимых миров:

```bash
python -m copytrading_sim.experiments \
  --config configs/experiments/standard.yaml --run-id iter2-standard
```

Повторное использование **ранее сохранённого** small-набора первой итерации:

```bash
python -m copytrading_sim.experiments \
  --config configs/experiments/reuse_small.yaml \
  --dataset artifacts/datasets/small_run/iter1-check --run-id reuse-iter1
```

Для `--dataset` в конфигурации нужен ровно один seed, совпадающий с seed набора.
Настройки генерации берутся из сохранённого набора, а не переопределяются задним
числом. Готовый набор копируется в эксперимент вместе с проверенными метаданными.
У малого набора очень короткие истории: такой прогон проверяет интеграцию,
но не даёт сильного доказательства качества модели.

## Архитектура

- `policies/base.py`: `Scorer.score(user_id, strategy_ids)` и
  `SlatePolicy.select(...)`; детерминированные первые K объектов и
  последовательная выборка Плакетта—Льюса.
- `baselines/`: случайная политика, публичная популярность, популярность по
  обучающей истории и привилегированный ориентир по совместимости.
- `policies/mixed.py`: существующая смешанная логирующая формула через новый интерфейс.
- `simulator/environment.py`: один запрос рекомендации, отклик, накапливаемая история.
- `datasets/splits.py`: временное разбиение целыми показами и разрешённые поля для обучения.
- `models/mf.py`: обучаемая матричная факторизация, контрольная точка, инференс.
- `evaluation/metrics.py`: отдельные протоколы совместимости, выбора и новых откликов.
- `experiments/`: конфигурация, запуск, сохранение численных результатов и графики.

`pipeline.py` остаётся генератором исходных историй с существующим механизмом
сбора. Он не обучает модели. Обучение и сравнительные эксперименты находятся в
`experiments/`. В `generate_exposures` добавлен необязательный аргумент `policy`,
но для внешних обученных моделей предпочтителен `SimulationEnvironment`.

Новая среда **не** обновляет автоматически финансовый профиль, позиции, популярность
или пользовательские предпочтения. Она хранит шаги и новые события; на разных
запросах можно передать новую версию рекомендателя. Это интерфейс для будущего
чередования обучения и показов, не готовый замкнутый обучающий цикл.

### Подключение обученной модели

```python
from copytrading_sim.datasets.exporters import load_run
from copytrading_sim.models.mf import LogisticMF
from copytrading_sim.policies import ScorePolicy
from copytrading_sim.simulator.environment import SimulationEnvironment

root = "artifacts/experiments/iter2-quick/seed_42"
data = load_run(f"{root}/dataset")
model = LogisticMF.load(f"{root}/mf.npz")
policy = ScorePolicy(model, name="mf")
env = SimulationEnvironment.from_tables(
    data.tables, data.config,
    start_step=data.config["simulation"]["exposures_per_user"],
)
result = env.step(0, policy, model_version="best_validation")
new_history = env.export_history()
print(result.copy_decisions[["strategy_id", "copied"]])
```

Будущий федеративный клиент может реализовать тот же `score`: использовать
локальный вектор пользователя и полученные глобальные параметры стратегий.
Среде не нужно знать, каким способом параметры были обучены.

## Модель и обучение

Оценка пары: `z_ui = b0 + b_u + b_i + p_u^T q_i`. Обучаем все эти параметры по
бинарной кросс-энтропии на **показанных** стратегиях с L2-регуляризацией. Вектор
`p_u` персональный уже в базовой матричной факторизации; это не неперсонализированная
модель. Оптимизатор Adam реализован на NumPy; производные проверяются численным
дифференцированием. Дополнительных зависимостей, PyTorch и графического интерфейса нет.

Это первая, пообъектная аппроксимация поведения. Сигмоида оценки не моделирует
совместное распределение выбора внутри списка и не является вероятностью,
что новая политика вызовет копирование. Модель не учитывает состав альтернатив
явно. Для проверки отклика используется отдельная модель пользователя симулятора.
BPR, обучение по целым спискам и нейросети здесь не реализованы.

Модель получает только `user_id`, `strategy_id`, `copied`; остальные разрешённые
поля истории служат разбиению и учёту показов. Непоказанные объекты не используются
как отрицательные примеры. Поля совместимости, архетипа и вероятностей отклика
не передаются через `learning_view`. Попытка передать полной таблицей диагностические
поля в `fit` отклоняется. Это разделение интерфейсов, не криптографическая изоляция.

Остановка — по минимуму проверочной бинарной кросс-энтропии с `patience` и
`min_delta`. Сохраняется лучшая модель, а не обязательно последняя эпоха. Возможен
выбор эпохи 0, если обучение не улучшило проверочную ошибку. Контрольная точка
содержит веса и ID-карты для инференса, но не состояние оптимизатора для возобновления.

## Три протокола — не смешивать

1. **Совместимость по полному каталогу.** Средняя совместимость первых K объектов,
   нормированный дисконтированный выигрыш с линейной значимостью, разрыв до
   идеального списка и охват каталога. Допускаются уже показанные/скопированные
   стратегии: это соответствует текущему симулятору, не является протоколом новизны.
2. **Предсказание выбора на отложенных показах.** Ранжируются только реально
   показанные альтернативы тестового списка. HitRate и NDCG считаются условно на
   том, что пользователь что-то скопировал. Списки без копирования учитываются
   отдельным числом; не получают фиктивную положительную метку. K строго меньше
   размера списка, иначе HitRate станет тривиально равным единице. Это не
   внеполитическая оценка качества новой политики.
3. **Новые показы при фиксированной модели.** Каждому методу даётся сброшенная копия
   того же мира и одинаковый бюджет запросов. Считаются фактическая частота и
   средняя условная вероятность копирования. Новые логи не используются для
   дообучения. `expected_compatibility_yield` означает вероятность-взвешенную
   совместимость с нулём за отказ; это не денежная полезность.

В каждом мире все обучаемые методы используют одинаковую исходную историю.
Обучение/проверка/тест разделены по глобальным индексам времени, целыми списками.
В нынешнем мире эти индексы обозначают порядок событий, а не реальные дни или
рыночные режимы. Векторы всех известных пользователей и объектов выделяются
заранее; проверка холодного старта пока не входит в протокол.

Публичная популярность — исходный признак мира, а популярность по обучающей
истории — число копирований в train. Последняя может усиливать смещение показа;
это намеренный ориентир, а не оценка "истинного качества". Смешанная исходная
политика и ориентир совместимости имеют привилегированную информацию. Ориентир
максимизирует **совместимость**, но не обязательно вероятность копирования.


Диагностические файлы содержат внутреннюю совместимость и вероятности. Не следует
брать все их колонки в обучение. При нескольких seed в таблицах сначала
усредняется качество пользователя, затем — качество мира. На графиках показаны
среднее и стандартное отклонение между мирами, **не доверительный интервал**.
Один seed предназначен для проверки запуска; три — небольшая предварительная
серия, а не окончательное статистическое доказательство.

## Что читать на графиках

- Совместимость против K и разрыв до ориентира: усвоено ли соответствие профилю.
- NDCG внутри тестового списка: предсказывается ли наблюдаемый выбор.
- Новые отклики: как рекомендатель влияет на поведение заданного симулятора.
- Качество по группам: не скрывает ли среднее слабые результаты для части пользователей.
- Обучение: признаки переобучения и выбранная по проверке эпоха.
- Охват: не сводятся ли рекомендации к одному общему списку.

Не устанавливаем тест "MF обязана быть лучше популярности": преимущество не
гарантировано. Если модель снижает обучающую ошибку, но проигрывает простому
правилу, это повод исследовать данные, объём истории, функцию потерь и регуляризацию,
а не менять формулу симулятора до удобного результата.

## Сохранённые ограничения

Финансовые прокси и симметрическая формула совместимости не изменены. Допустимая
просадка там пока трактуется как желаемая близость, а не жёсткий верхний предел;
это остаётся содержательным ограничением прототипа. Прямые показатели риска,
устойчивости и `sortino_proxy` не стали реальными финансовыми оценками.

Положение внутри списка сохраняется, но текущая модель выбора не имеет
позиционного эффекта. Популярность и капитал под копированием не обновляются.
Список допускает не более одного выбора и повторный выбор на другом шаге.
Вероятности Плакетта—Льюса условны на предыдущие позиции; при шумовых оценках —
также на реализованный шум. Это не готовые маргинальные вероятности для
внеполитической оценки, и такая оценка не реализована.

Основные источники подхода: RecSim (arXiv:1909.04847), Krichene и Rendle,
On Sampled Metrics for Item Recommendation (2020), документация NumPy по
независимым потокам случайности. Их идеи используются как методологические
ориентиры; калибровка по реальным данным копи-трейдинга не заявляется.
